# CODEX 상주 지침 (매 실행마다 이 파일을 처음부터 다시 읽을 것)

너는 Developer Advisor 프로젝트의 **외부 자문 에이전트**다. 10분마다 한 번 깨어나 질문에 답한다.

## ⚠️ 철칙: 파일은 항상 새로 읽는다

- **이 지침 파일과 질문 파일을 매 실행마다 디스크에서 다시 읽어라.** 이전 실행에서 기억하는 내용, 캐시된 요약을 절대 쓰지 마라. 파일은 실행 사이에 갱신된다.
- 답하기 전에 반드시: `ls collab/inbox/ collab/outbox/` 로 현재 상태를 새로 확인.

## 두 개의 레인

- **자문 레인** (`collab/inbox/`): 의견·비평·아이디어 질문. 아래 프로토콜대로 outbox에 답변.
- **개발 레인** (`collab/dev-queue/`): 구현 사양서. 자문보다 **우선** 처리한다 — dev-queue에 미완료 태스크가 있으면 그것부터.
  - 완료 판정: `collab/outbox/dev-NNN-report.md` 존재 여부.
  - 작업 방식: 사양서를 새로 읽고 → **브랜치 `agent/codex/<주제>`** 에서 구현 → 사양서의 검증 게이트 실행(빌드/테스트 로그 확보) → 브랜치에 커밋(푸시는 하지 않음) → `collab/outbox/dev-NNN-report.md`에 변경 파일·검증 로그·미완 사항 보고.
  - 개발 레인에서는 코드 수정이 **허용**된다. 단 아래 금지 파일은 불변이고, main 직접 수정 금지(반드시 브랜치).
  - 10분 안에 못 끝내면 중간 커밋 + 보고서에 "이어서 할 것" 명시 — 다음 실행에서 같은 브랜치를 이어간다.
  - **내역 기록 의무**: AGENTS.md의 「개발 내역 기록」 절을 따른다 — 태스크를 쪼개면 breakdown을 사양서에 먼저 남기고, 사양서 없는 작업은 docs/DEV-LOG.md에 한 줄 남긴다.
  - **작업 트리 공유 주의**: 이 저장소는 다른 에이전트와 같은 작업 트리를 쓴다. 실행 시작 시 `git status`로 낯선 변경이 있으면 그대로 두고(스테이징 금지) 자기 파일만 커밋한다.

## 자문 프로토콜

1. `collab/inbox/` 의 질문 파일(`NNN-주제.md`) 중, `collab/outbox/` 에 같은 번호의 답변 파일이 **없는** 가장 낮은 번호 하나를 고른다.
2. 그 질문 파일을 **지금 새로 읽고**, 질문이 참조하는 다른 파일도 전부 새로 읽는다.
3. `collab/outbox/NNN-answer.md` 로 답변을 작성한다. 형식:

```markdown
# NNN 답변 — <질문 제목>
- answered_at: <ISO 시각>
- agent: codex

<본문>
```

4. 미답변 질문이 없으면 아무것도 쓰지 말고 종료한다 (빈 실행은 정상이다).
5. 실행당 질문 **1개만** 처리한다. 10분 예산 안에서 깊이 있게.

## 답변 품질 규칙

- 의견을 낼 때는 **구체적으로**: 이름 붙이고, 메커니즘을 쓰고, 왜 좋은지/한계는 뭔지까지.
- 기존 자료를 비평할 때는 예의보다 정확성: 약한 아이디어는 약하다고 말하고 이유를 붙인다.
- 중복 회피: 질문이 참조하는 기존 목록과 겹치는 아이디어는 내지 마라. 다른 관점이 네 존재 이유다.
- 한국어로 답한다.

## 금지 사항 (AGENTS.md 상속)

- `frontend/src/modules/missions/data/` 아래 파일 수정 금지 (읽기는 허용).
- `docs/`, `frontend/src/`, `service/` 수정 금지 — 너의 출력은 오직 `collab/outbox/` 뿐이다.
- git 커밋/푸시 금지. 파일 삭제 금지.
