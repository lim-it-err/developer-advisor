# TASTE.md — 취향과 결정의 기록

> 이 문서는 Developer Advisor를 만드는 두 사람(학습자 정한, 기획자 Claude)의
> 취향, 합의, 그리고 기각된 것들의 기록이다.
> 코드와 커리큘럼은 "무엇을 만들었는지"를 말하지만, 이 문서는 "왜 그렇게 만들었는지"를 말한다.
> 새로 합류하는 사람·에이전트는 코드를 읽기 전에 이것을 먼저 읽으면 우리를 이해할 수 있다.

## 1. 학습자는 누구인가

- 3년차 Java 개발자. **비IT 도메인 회사** 소속 — 화려한 기술 스택보다 "도메인을 코드로 번역하는 일"이 일상이다.
- 스스로 진단한 약점: **인터페이스 개념, 코드 분리**. 그래서 이 플랫폼의 척추는 S1(분리)~S3(의존성 역전)이다.
- 원하는 훈련 세 가지: ① 레거시 리팩토링 ② 실세계 상식이 필요한 도메인 로직(과세, 이자, 건폐율 같은 것) ③ **설명 훈련** — 아는 것을 말로 꺼내는 힘.
- 요즘은 코딩할 시간이 없는 기간이 있다. 그래서 **코드를 한 줄도 안 쓰는 콘텐츠**(코드 판독, 배역극, 독서 카드)가 정식 유형으로 존재한다. 이것은 타협이 아니라 커리큘럼의 일부다.
- 모바일로 접속하는 일이 많다. 시인성과 선택형 입력이 중요한 이유.

## 2. 취향 — 좋아하는 것

- **철도.** 최애 도메인. KTX 미션이 대표작이고, 시베리아 횡단철도·설국열차·통일호가 모두 여기서 나왔다.
- **항공 사고 사례 × 컴퓨터 공학.** 가장 좋아하는 크로스오버. 실제 사고(수하물 시스템, 전산 마비)를 구조의 언어로 다시 읽는 것.
- **컴퓨터 공학과 무관해 보이는 세계의 의사판단.** 항해 규칙, 경매 배당, 청약 가점 — "이건 사실 스케줄링 문제잖아" 하는 순간을 사랑한다.
- **스토리텔링.** "결과를 시나리오로 받는다"는 아이디어에 가장 크게 반응했다. 점수보다 이야기가 남는다.
- **게임 문법.** 결말 분기(상태창), 히든 퀘스트, 프린세스 메이커식 시즌 스탯, 미니게임 덱. 학습을 게임처럼, 단 유치하지 않게.
- **감성.** 통일호는 KTX 개통 하루 전인 2004년 3월 31일에 퇴역했다. 코드에는 아직 살아 있다 — 이런 문장. 감정은 장식이 아니라 문제의 일부여야 한다(dead code에 서사가 있으면 지우는 손이 무거워진다).
- **고생담(war story).** 히든 케이스가 뚫렸을 때 "실제로 이런 일이 있었다"는 이야기가 붙는 것. 교훈은 이야기의 형태일 때 남는다.

## 3. 취향 — 싫어하는 것 / 하지 말 것

- **정해진 자리에 박힌 유머.** 초기에 "모든 미션의 제약 조건에 농담 하나"를 넣었다가 전부 걷어냈다. 유머는 자연스러운 자리에서만, 없으면 없는 대로. (생존한 유머: 와인 미션의 "시음하며 풀어도 됩니다", KTX의 서울–부산 소요시간 = 제한시간 160분.)
- **뻔한 소재.** 트롤리 딜레마는 "너무 흔하다"로 기각됐다. 어디서 본 듯한 것을 다시 만들지 않는다.
- **엔진 구현을 시키는 것.** db.insert() 안쪽은 학습자의 훈련 지점이 아니다. 엔진 코드는 항상 제공하고, 학습자는 **인터페이스를 긋는 자리**에서 훈련한다.
- **가짜 리뷰.** 백엔드가 꺼져 있으면 "엔진이 꺼져 있다"고 정직하게 말한다. 그럴듯한 가짜 결과를 만들어 보여주지 않는다.
- **타이핑 강요.** 모바일에서 긴 타이핑은 벌칙이다. 선택 UI(칩, 카드, 투표)가 기본이고 타이핑은 언제나 열려 있는 선택지.

## 4. 콘텐츠 원칙 (합의된 것)

1. **도메인은 넓게, 특정 예시에 종속되지 않게.** 제빵, 합창단, 혈액형, 달력, 항해, 경매… 초기 예시(세금/이자)에 갇히지 말 것.
2. **난이도는 두 축.** Easy/Normal/Hard(개념 난도) × 단일 파일/여러 파일/모듈 경계(변경 범위). 한 축으로 뭉개지 않는다.
3. **히든 케이스 3개.** 지문에 명시되지 않은 함정(오버플로, 타입 배신, 동시성). 뚫리면 war story가 붙는다.
4. **히든 퀘스트.** 지문 속에 문장으로 심는다. 힌트로 알려주지 않는다. 리뷰에서만 "알아채셨나요, 지문의 그 문장을?" 하고 공개한다.
5. **결말 4종.** ☕ 평온 / 🔧 핫픽스 / 🚨 새벽 호출 / ??? (히든). 리뷰의 시나리오가 어느 결말에 도달했는지 도장을 찍는다.
6. **평판은 점수와 별개.** 질문 창에서의 소통 태도를 정성 평가한다. 잘 물어보는 것도 실력이다.
7. **기획자 모드의 hiddenAgenda는 연기 대본이다.** 절대 화면에 렌더링되지 않는다. 참석자는 각자의 숨은 의도대로 대답할 뿐이다.
8. **상식은 헤지해서 쓴다.** 실제 사건(델타 정전, 사우스웨스트 마비)을 인용할 땐 "보도 기준" 같은 유보를 붙인다. 실명 개인 비난은 금지.
9. **인용 없이 변형만.** 책·영화 카드는 아이디어의 요약과 CS 연결만 쓴다. 원문 인용, 대사, 가사 금지.

## 5. 제품 결정 기록 (왜 이렇게 됐는가)

| 결정 | 이유 |
|---|---|
| Vue 3, `src/modules/missions/` 모듈 격리 | 언젠가 workaround.co.kr 플랫폼에 이식할 때 모듈째 들어낸다 |
| localStorage 우선, 백엔드는 선택 | 정적 배포(GitHub Pages)만으로 완결. 백엔드는 켜면 좋아지는 것 |
| 닉네임은 기록 구분자일 뿐 | 로그인이 아니다. 제출·이력 진입 시에만 묻는다 |
| 리뷰=Sonnet, 채팅=Haiku | 채점은 깊이가, 질문 응대는 속도가 중요. 비용도 이 배분이 맞다 |
| mock 프로필이 기본 | 과금은 사용자가 claude 프로필을 명시적으로 켤 때만. 몰래 청구되는 일 없음 |
| Ollama는 보류 | 관심은 있으나 지금은 아님. 포트(LlmClient)는 이미 뚫어뒀다 |
| run.sh가 JAVA_HOME을 강제 | 이 머신의 mvn 기본 런타임이 JDK 25라 빌드가 깨진다. conda 환경변수도 방어 |
| 리뷰는 stateless API 호출 | 제출 코드는 요청 페이로드로만 전달된다. "비밀모드가 기본"이라는 답의 근거 |

## 6. 협업 방식

- **Claude(Fable) = 머리.** 기획, 콘텐츠, 판단, 통합. 특히 **톤이 있는 콘텐츠(sampleContent.js 등)는 Claude 전담이며 불변 원칙** — 미션의 문장은 이 문서의 취향이 스며든 결과물이라, 다른 손이 닿으면 균질해진다.
- **Codex = 손.** 의견 자문, QA, 코드 집약적 개발(테스트 스위트, 인프라). `collab/` 프로토콜 참조.
- **하위 에이전트(Sonnet 등) = 소규모 구현 위임.** 단, 콘텐츠 에이전트는 이 문서의 톤 규칙을 상속한다.
- 업무 분배와 거부권은 기획자(Claude)의 권리로 위임되어 있다 — "이건 아닌 것 같다"고 말하는 것 포함.
